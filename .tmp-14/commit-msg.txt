批 14 第二步（路 A）：库构建改为 tsc 输出模块树，新增 /core /webgl2 /webgpu 子入口

## 第一步测量结论（负结果，三种打包器一致）
单文件 ESM + sideEffects:false 下，**只用 WebGL2 的消费方与「两个后端都要」的消费方
产物体积逐字节相同**（差值 -2 字节，就是 'webgl2' / 'auto' 那处字符串），
且产物里 WebGPUAdapter / WebGPUDevice / WebGPURenderPassEncoder 等完整符号全部在位：
rollup 585003/585001、esbuild 291738/291736、vite 479421/479419（minified）。
根因是 src/factories/default-registry.ts 静态 import 了两个后端的 Adapter，
backend:'webgl2' 是运行时字符串 => 打包器摇不掉。故第一步判定：树摇不够用，进入第二步。

## 第二步：tsc 模块树（用户/负责人选定的路 A）
- tsconfig.build.json：noEmit:false + outDir:dist + rootDir:src，一次产出
  每源文件一个 .js/.d.ts/.map（不再有 dist/types/**，也不再 emitDeclarationOnly）。
- 新入口平铺在 src 根下：src/core.ts、src/webgl2.ts、src/webgpu.ts（+ 原 src/index.ts），
  因此产物是 dist/core.js、dist/webgl2.js、dist/webgpu.js —— **没有 entries/ 目录**。
- package.json：exports 只增不改（"." 仍在），新增 ./core ./webgl2 ./webgpu；
  main/module/types 指向 ./dist/index.js / ./dist/index.d.ts。
- scripts/build.mjs：只做「清空 dist -> tsc -p tsconfig.build.json -> postbuild」。
  不再有 vite build；vite.config.ts 只保留 dev server（server.watch.ignored 原样未动）。
- scripts/postbuild.mjs：@webgpu/types reference 改成一个**固定的 4 项小列表**（不遍历生成）。
- 硬前提已全量校验（.tmp-14/verify-emit.mjs）：552 条相对说明符、0 条缺失、0 条非 .js 结尾；
  四个入口都能被 Node 真实 import => tsc 产物是可直接消费的 ESM，无需说明符重写/生成脚本。

## 公开面变化
新增三个子入口（只增不改）。为消除子入口 re-export 的 TS2308 歧义，两处**后端索引**改名：
src/webgl2/index.ts: TextureSampleType -> GlTextureSampleType（与 core 的同名类型不是一回事）
src/webgpu/index.ts: PipelineCache -> WebGPUPipelineCache（core 那个是接口，这个是类）。
这两个模块**不在主入口的公开面上**（src/index.ts 不导出任何后端），仓库内无引用，故无影响。
