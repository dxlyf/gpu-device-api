gpu-device-api 示例汇总

同一个库的两种用法：gfx 便捷层（声明式材质/几何体/相机）， 与 core 只用手写 API（着色器、缓冲、管线、通道全部自己来）。 两个后端都一样：用 ?backend=webgl2|webgpu|auto 切换，默认 auto（优先 WebGPU，失败回退 WebGL2）。

core 层示例（不使用 gfx 便捷层）

三角形core
最小的一次绘制：交织顶点缓冲（position 2 + color 3，步长 20）、layout: 'auto'、 没有 uniform 也没有 bind group。?verify=1 做像素自检。
立方体core
3D 必备件：投影/视图矩阵、uniform 块的字节打包（std140 与 WGSL uniform）、 bind group layout、带深度的管线。两个 stage 都要自己声明 uniform 块。
贴图core
createTexture + queue.writeTexture + createSampler， 纹理/采样器/uniform 放在同一个 bind group；采样器名字要按 <纹理名>_sampler 配对。
mip 路径对比core
JS 盒式 mip 链 vs 后端生成（WebGL2 的 generateMipmap / WebGPU 的 render pass 降采样）： 逐级读回真实字节比对，并给出 sRGB 与 2048² 耗时数据。
实例化core
每实例属性（stepMode: 'instance'）：一个网格、1 次 draw call 画 N 个实例。 ?count=2000…20000 调数量。
批量core
N 个物体各一次 draw call、共用一条管线；每个物体用自己的 动态偏移 读 uniform （hasDynamicOffset: true + setBindGroup(1, bg, [offset])）。
风景core
天空渐变 + 太阳 + 两层山脊 + 实例化树林（520 棵、2 次 draw call）+ 一条清澈的河： 先画河床、再画半透明水面，fresnel 让垂直看更透明、掠射角更反射天空。 6 条管线 / 8 次 draw call，?only=sky|ridge|terrain|bed|tree|water 可逐层排查。
性能基准core
2000 / 5000 / 10000 / 20000 / 40000 个图形逐档计时（帧耗时、CPU 提交、每秒三角形）， 实例化与「逐个 draw」两种模式对照。别加 --virtual-time-budget。
异步贴图core
createImageBitmap 异步解码路径：URL / Blob / 已有 bitmap / canvas 四条入口， 读回第 0 级逐字节比对（两后端 maxDiff=0）。支持 6 种格式，不再锁死 rgba8unorm。
管线预热与编译诊断core
把着色器编译/链接挪出渲染循环：createRenderPipelineAsync（WebGPU 真异步） 与 KHR_parallel_shader_compile（WebGL2，扩展缺失时如实降级为 sync）。 编译错误能给出真实行号。
「不使用深度」的语义回归core
depthStencil: { format: null } 与「不声明」都必须表示不使用深度。 含一个反向对照（显式写深度时后方物体必须被遮住），防止判据假通过。
离屏 MSAAcore
renderbufferStorageMultisample + blitFramebuffer resolve。 判据是真实截图里的中间色像素：samples=1 时 0 个、 samples=4 时 3203 个（恰好 3 种 = sampleCount−1）。 采样数不支持时明确报错，不静默降级。
渲染到纹理的行序coregfx
「先渲染进纹理、再采样上屏」这条链路在两个后端必须给出同一幅画面。 本库约定纹素 (0,0) 在左上；WebGL2 的渲染目标原生是自下而上， 所以 core 层显式提供统一用的 helper，gfx 层自动统一。
设备丢失core
真的丢掉 WebGL2 上下文（WEBGL_lose_context）、真的销毁 WebGPU 设备， 验证后续提交会抛 DeviceLostError 而不是静默丢弃命令。 抽象层内无法自动恢复，只能新建设备并重建资源 —— 这条如实写进文档。
Computecore
WebGPU 上 dispatchWorkgroups 计算 4096 个值，读回逐元素严格相等 （校验和一致，不是阈值判据）。WebGL2 没有 compute，两条入口都抛带前缀的错误并给出替代方案。

gfx 便捷层示例

场景 demogfx
五行画出东西的完整场景：lil-gui 调参、切换后端、几何体/材质/光照切换、 ?verify=1 像素自检。
实例化gfx
用 { format, stepMode: 'instance' } 声明实例属性 + drawInstanced()， 与 core 版对照可以看到便捷层省掉了哪些样板。
批量gfx
每个物体一次 draw()，各自的 model 与 uniform 由 uniform arena 自动分配区间并做动态偏移。
冒烟测试gfx + core
17 项检查：设备创建、管线交叉校验、canvas 与离屏目标的像素级断言、以及各类错误路径。 结果写在 data-smoke-result。 注意：本页只跑 WebGL2（着色器是 GLSL、读回用 gl.readPixels、 另有三条 WebGL2 专有的错误断言），所以它也输出 data-smoke-backend="webgl2" —— 别把它当成「两个后端都验证过」。WebGPU 的 core 层覆盖见 depth / instancing / device-lost / compute。
画布深度测试回归gfx + core
先画近处红四边形、再画远处绿四边形（都 depthTest: true），中心像素必须是红 —— 否则说明画布渲染通道没有 depth attachment、DEPTH_TEST 被悄悄关掉。 读回的是 canvas 本身（WebGL2 走 readPixels，WebGPU 走 copyTextureToBuffer）。用 ?backend=webgl2|webgpu 各跑一遍， 结论在 data-depth-result / -pixel / -format。
管线预热（gfx 层）gfx
renderer.prewarm() / renderer.compilationInfo()： 预热后首个使用该管线的帧耗时降一个数量级。 实测 WebGPU 469.9ms → 7.4ms（真异步）；WebGL2 347.7ms → 0.20ms （本机缺扩展，mode:'sync'，如实透出）。
性能基准（gfx 层）gfx
每个物体一次 draw() 逐档计时，CPU 提交与 GPU 执行两列分开 （renderer.stats.gpuFrameTime，取不到就是 null 而不是 0）。 ?counts= 调档位、?ab=cull 做剔除开/关配对测量 （20000 个物体时 draw calls 20000 → 10617）。

无头验证：每个页面都会把自己那次的结论写进 <html data-*>， 无头浏览器 --dump-dom 抓一下就知道有没有画出来 —— 例如 data-triangle-lit、data-texture-distinct、 data-batch-lit、data-depth-result、data-benchmark-results。

两个坑：--virtual-time-budget 会让 performance.now() 跟着虚拟时间跳， 性能基准千万不要加；测 WebGPU 时不要同时加 --use-angle=swiftshader （那个组合下 requestAdapter() 会返回 null）。WebGPU 的异步返回也抓不住 --dump-dom，请用 node scripts/verify-headless.mjs（CDP + 真实时间轮询）。

源码与用法见仓库根目录的 README.md；每个示例的 core-*.ts 顶部注释都写了 这一页要演示什么、以及对应的 core API 调用点。
