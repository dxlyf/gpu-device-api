mipmap 降采样用的 WGSL / bind group layout 能不能真的建起来、跑对层

本页**不导入本库**，只把 src/webgpu/resources/WebGPUTexture.ts 里那两段 WGSL 原文与对应的 bind group layout / pipeline 描述照抄一份，交给原生 device 亲自验。

为什么需要这一页：vitest 里的原生 device 是 mock， createShaderModule 永远返回 {} —— WGSL 写错（签名不匹配、绑定类型、 uniform 布局）在 node 侧**一个都发现不了**，只会在浏览器里第一次真正生成数组 / 3D 的 mip 时 报错或画错。批 03 的数组路径是全新着色器，必须单独验。

步骤：① 两段 WGSL 编译 + 建管线；② 对照 A：writeBuffer → mapAsync 读回（验最基本的读回路径）；③ 对照 B/B2：staging 填纹理 → 渲染 → 读回、 以及源纹理原样拷回（验「填纹理 + 采样 + 渲染 + 读回」全链路）；④ 双层数组纹理每层内容不同， 逐层降采样后比字节。

本机（无头 Chrome + swiftshader）实测结论：① 两段 WGSL 都编译通过、两条管线都建得起来 （这一步抓出过一个真错：数组着色器最初写成 textureSampleLevel(tex, samp, vec3f(uv, layer), 0.0)， 而 texture_2d_array 没有 vec3 坐标这个重载，WGSL 直接拒绝 —— node 侧 mock 永远发现不了）； ②③ 两组对照全通过；④ 本机**数组纹理采样错位**：连「层号写死 0u + 源 view 只覆盖第 0 层」 都采到第 1 层的值，所以第 4 步在本机**给不出可用结论**，数组层的 subresource 选择改由 test/webgpu-mipmap-array.test.ts 的 mock 覆盖。
