原生的 mapState / mappedAtCreation 到底是什么语义

这个探针**不导入本库**：它只读原生 GPUBuffer 的 mapState 与 mappedAtCreation，用来核对批 03（#24）在 WebGPU 后端上的三态实现假设。 用法（WebGPU 需要 --enable-unsafe-webgpu）： 

node scripts/verify-headless.mjs --chrome "<chrome>" \
  --url "http://localhost:<port>/examples/native-mapstate-probe.html" \
  --wait probeResult -- --enable-unsafe-webgpu

本机实测（无头 Chrome + swiftshader，批 03 记录）：
stateAfterCreate=unmapped、statePending=pending、 pendingRangeError=threw（DOMException）、stateMapped=mapped、 mapAsyncResolves=undefined、rangeAfterAwait=ArrayBuffer、 doubleMapError=DOMException、stateAfterUnmap=unmapped、 detachedByteLength=undefined（detach 后读长度抛错）、 stateAfterDestroy=unmapped、macStateAfterCreate=mapped、 macRangeKind=ArrayBuffer、macOverlapError=DOMException、 macDestroyWhileMapped=no-error、destroyedMapAsync=DOMException。
